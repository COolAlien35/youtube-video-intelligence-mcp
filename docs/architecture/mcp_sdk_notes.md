# MCP Python SDK verification · 25 November 2026

**Dependency request for A.** Lock `mcp==2.3.0` (MIT). The official distribution installed on Python 3.12 and exposes MCPServer under mcp.server. Phase 2 also needs FastAPI and a local ASGI runner. The SDK HTTP client uses httpx2 in this release; use its ASGI transport for the offline client smoke test. Keep the ownership of the dependency list and lockfile with A. [PyPI release](https://pypi.org/project/mcp/2.3.0/) · [SDK source](https://github.com/modelcontextprotocol/python-sdk/tree/v2.3.0)

| Question | Verified behavior and project decision |
|---|---|
| How does the endpoint mount? | Construct MCPServer, call streamable_http_app with the child route /mcp and mount the returned ASGI app at the parent root after /health. Enter the child router’s lifespan from the FastAPI lifespan. This gives a single /mcp path. [ASGI integration](https://py.sdk.modelcontextprotocol.io/run/asgi/) |
| What state survives each request? | The July revision has no protocol-level sessions. Select stateless_http=True. Approval state belongs in principal-scoped application storage. The SDK also supports legacy clients. July discovery and the legacy initialize handshake are separate flows. [Transport specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) |
| How are tools typed? | MCPServer.add_tool registers a typed callable. Parameter annotations produce the input schema; a typed object return produces structuredContent and an output schema. Keep the principal out of client inputs. [SDK tool documentation](https://py.sdk.modelcontextprotocol.io/servers/tools/) |
| Can Phase 6 use MRTR? | Yes. The SDK supports InputRequiredResult. A client can resubmit the call with answers and echoed requestState. Phase 6 must verify immutable proposal, principal, account, expiry and one-time approval server-side. Client interoperability with the target Claude Desktop build is TBC. [SDK MRTR](https://py.sdk.modelcontextprotocol.io/handlers/multi-round-trip/) |
| Which origins and hosts are accepted? | The specification requires HTTP 403 for an invalid supplied Origin and recommends loopback binding locally. It does not require rejection solely for an absent Origin. Phase 2 accepts absent Origin and exact configured values, rejects duplicates, and keeps the SDK’s Host check on the MCP endpoint for loopback hosts. Host checking is SDK hardening; a production host policy belongs with Phase 3. [Transport security](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http#security--endpoint) · [SDK transport security](https://github.com/modelcontextprotocol/python-sdk/blob/v2.3.0/src/mcp/server/transport_security.py) |

The tracker had no Phase 2 dependency-request issue at verification. This PR serves as the dependency handoff to A. No live provider or external credentials are needed for the smoke test.
