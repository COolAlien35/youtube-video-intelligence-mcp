# Phase 3 threat model and verification evidence

Scope: MCP client → service authentication → principal-scoped storage → delegated Google provider. The MCP service token establishes the caller. A Google grant authorizes account actions. Metadata is untrusted input. The audit journal accepts classified events and evidence references only. Tests below use synthetic data; “pending” means a complete control has no passing end-to-end proof yet.

| SRS §7 threat | Control and expected result | Evidence available / proof still required |
|---|---|---|
| Expired or revoked OAuth | Halt account-scoped work and return safe reauthorization guidance. Never send an MCP access token to Google. | Provider mapping suite covers invalid_grant. [D’s auth tests](https://github.com/COolAlien35/youtube-video-intelligence-mcp/pull/42) verify safe HTTP status. Pending B/C integration: revoke a fake grant, attempt a read, verify reauthorization and zero writes. |
| Cross-tenant access | Verify issuer, audience, expiry and signature. Derive principal server-side. Bind encrypted grant to its principal as AAD and scope storage reads, writes and deletes. | Fixture account isolation tests exercise the adapter. Pending A/B/C: principal B cannot read, decrypt, delete or approve principal A’s records; repeated subjects from separate issuers remain distinct. |
| Prompt injection | Treat titles, captions and descriptions as data. Deterministically validate hard constraints and require explicit approval. | Live adapter disabled; this alone cannot prove injection resistance. Pending C and playlist implementation: synthetic metadata containing instructions leaves proposal and write counters unchanged until authorized confirmation. |
| Stale or edited approval | Immutable digest, principal/account binding, five-minute expiry and atomic single use. | Pending proposal implementation: edit an ordered item, expire an approval using FakeClock, and reuse a consumed approval. Each must reject before any provider write (TQ-10). |
| Secret disclosure | Encrypted, key-versioned refresh tokens; minimal public errors; redact messages, structured extras and OAuth fields. Keep journal details restricted. | Existing test_common_logging.py, plus test_redaction_p3.py and test_ledger.py on D’s branches. Pending A/C: encrypted persistence and wrong-principal decryption tests, then inspect fake callback and refresh logs. |
| Quota exhaustion | Reserve both independent budget counters atomically and reject excess work before calling the provider. Use a shared Pacific quota day. | tests/unit/quota/test_quota_ledger.py exercises concurrent reservations, unchanged ledger on denial and midnight rollover. The cost schedule, settlement overruns and Phase 4 per-principal limits remain separate acceptance items. |

The transport suite also checks 403 on an untrusted Origin. The unauthenticated 401 and verified-principal tool success require B’s middleware and C’s fake issuer. The [policy gate tests](https://github.com/COolAlien35/youtube-video-intelligence-mcp/pull/44) cover missing evidence, partial clearance, fixture access and refusal of a live adapter. C must link the integrated results into the RTM before sign-off.
