# Using the Obsidian vault

Open the brain folder as a vault and start at [[index]]. The SDLC specifies an inbox, unnumbered PARA folders, an index and a run log. Earlier project notes in the repository’s second-brain folder retain their original paths. Repository Markdown links to those sources can also be opened on GitHub.

| Location | What belongs here |
|---|---|
| inbox/ | Newly captured sources awaiting refinement |
| projects/ | Work with a deadline, including stage reviews and query results |
| areas/ | Distilled guidance for recurring engineering decisions |
| resources/ | Source notes retained after refinement |
| archive/ | Inactive material whose provenance is still needed |
| _templates/ | Ingest, refinement and query forms |

**Ingest.** Summarize one source per note in your own words. Name it ingest_PERSON_topic.md. Include source sections, relevant IDs, actual issues or PRs when available, and uncertainties. Use the seven headings in the ingest template.

**Refine.** Check a group of source notes, move classified notes into PARA, consolidate duplicate conclusions and repair links after moves. Preserve original sources and authors. A distilled note explains a decision and its limits.

**Query.** Answer a project question from distilled notes, link the supporting evidence and record what remains unknown. Record every run in [[log]]. Use unique filenames for wikilinks and relative Markdown links for files outside the vault. Submit edits through review. Each author commits their own notes.
